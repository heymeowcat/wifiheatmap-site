# WifiHeatmap — Website

Official marketing site for **WifiHeatmap: Signal & Analyzer**, the free, fully
offline Android Wi-Fi analyser and indoor site survey app.

**Live URL:** https://heymeowcat.is-a.dev/wifiheatmap-site/

---

## Stack

| Concern | Choice | Why |
| --- | --- | --- |
| Framework | **Astro 5** | Static HTML by default, zero JS unless you ask for it |
| Styling | **Tailwind CSS 4** | Utility-first, with a custom design-token layer |
| Interactive showcase | **Vanilla JS + Astro** | The previous React + Framer Motion build shipped ~85 kB of JS; this ships **1 kB gzipped** |
| Icons | Inline SVG | No icon-font request, no third-party origin |
| Fonts | Self-hosted variable WOFF2 | 62 kB for both families, preloaded, `font-display: swap` — no render-blocking Google Fonts request |
| Images | `astro:assets` → WebP | 791 kB JPEG → 16–46 kB WebP, responsive `srcset`, explicit dimensions |
| Sitemap | Custom endpoint | One `sitemap.xml` with per-URL priority/changefreq, generated from the same constants as `robots.txt` |
| Schema | Hand-written JSON-LD | `Organization`, `WebSite`, `MobileApplication`, `FAQPage`, `BreadcrumbList`, `Article`, `CollectionPage` |
| Hosting | GitHub Pages | Served from `dist/` under the `/wifiheatmap-site` base path |

## Design system

The visual language comes straight from the app — most of all from the **app
icon itself**, which is a rainbow RF heatmap with the Wi-Fi glyph cut out of it.

- **Heat ramp** — `#2563eb → #0ea5e9 → #22d3ee → #4ade80 → #fde047 → #fb923c → #ef4444`
  (blue → cyan → green → yellow → orange → red). Used for the animated haze
  backdrop, the signal legends, the gradient headings and the rainbow halos
  behind every screenshot.
- **Light frosted glass** — `backdrop-filter: blur(26px) saturate(180%)` over a
  66% white wash, with a 1px white border, a 1px slate ring and a blue-tinted
  drop shadow. Exposed as the `glass` utility; `glass-rainbow` adds the heat
  ramp as a pigment wash on top of it.
- **Dark-on-rainbow buttons** — the primary CTA is a cyan → sky → indigo
  gradient with near-black text, exactly like the app icon. White text on that
  ramp fails contrast at the cyan end, so the buttons are dark instead.
- **Canvas** — `#eef4fd` page, alternating `#ffffff` section washes with
  hairline rainbow rules.
- **App icon as the favicon** — `public/favicon.svg` is a vector recreation of
  the app icon (rounded tile, layered heat gradients, Wi-Fi glyph), with the
  PNG app icon as the fallback for `icon-192` and `apple-touch-icon`.

The heat haze is built from layered radial gradients blended with `multiply`
and animated with `transform` only, so it composites on the GPU and never
triggers layout. All animation is disabled under `prefers-reduced-motion`.

> **Gotcha:** do not add `-webkit-backdrop-filter` next to `backdrop-filter` in
> `global.css`. The CSS minifier treats the prefixed and unprefixed property as
> the same and keeps only one of them — it kept the `-webkit-` one, which
> silently killed the frosted glass in every browser that does not support the
> legacy alias. Write the standard property only and let the bundler add the
> prefix.

## SEO & performance

### What is implemented

- Unique `<title>` (≤ 60 chars) and meta description (≤ 160 chars) on every page
- Exactly **one `<h1>`** per page, with no heading-level skips
- Absolute, trailing-slash canonical on every page
- `index, follow, max-image-preview:large, max-snippet:-1, …` robots directives
  (only the 404 is `noindex`)
- Full Open Graph + Twitter card set, including a real 1200×630 `og:image`
- Descriptive `alt` text on every meaningful image; decorative icons are
  `alt=""` **and** `aria-hidden="true"`
- Breadcrumb navigation with matching `BreadcrumbList` schema
- `FAQPage` schema on every FAQ block
- `MobileApplication` schema with `featureList`, `offers`, `permissions` and
  `aggregateRating`
- Single `sitemap.xml` with priorities, `changefreq` and honest `lastmod`
- `robots.txt` generated from the same constants as the sitemap
- HTTPS enforced, with HSTS and modern security headers
- No third-party requests at all — fonts, icons and images are first-party

### Core Web Vitals budget

| Metric | Target | Actual (gzip) |
| --- | --- | --- |
| HTML + CSS + JS (homepage) | < 60 kB | **38 kB** |
| JavaScript | < 10 kB | **1 kB** |
| Fonts | < 80 kB | **62 kB** (2 variable files) |
| LCP element | — | inline SVG, no image request |
| CLS | 0 | every image has explicit `width`/`height`; tab panels share one grid cell |

### Regression check

```bash
npm run build && npm run seo:audit
```

`scripts/seo-audit.mjs` walks every generated page and fails the build on:

- missing or duplicate `<h1>`
- heading-level skips
- missing / duplicate / over-length `<title>` or meta description
- a canonical that points outside the site or lacks a trailing slash
- `noindex` on an indexable page
- missing Open Graph or Twitter tags, or a missing `og:image` file
- invalid JSON-LD
- `<img>` without `alt`, without dimensions, or without a `loading` attribute
- **broken internal links** (including the base-path prefix)
- a `sitemap.xml` that is missing a page, or that lists a URL outside the base
- a `robots.txt` that does not point at the sitemap

Current status: **0 errors, 0 warnings.** Lighthouse: Accessibility 100,
Best Practices 100, SEO 100.

### ⚠️ One manual step: the source repository is private

`github.com/heymeowcat/WifiHeatmap-Android` is currently **private**, so the site
deliberately does not link to it — a dead link damages trust and SEO, and a
`sameAs` entry pointing at a 404 is worse than no entry at all.

To turn the source-code links on across the whole site (footer, about page,
changelog, resources page and the `Organization` schema), do both of these:

1. Make the repository public on GitHub, and
2. flip the flag in `src/config.ts`:

   ```ts
   export const APP_REPO_PUBLIC = true;
   ```

Nothing else needs to change — every link and the schema entry are already
wired to that flag.

## Search Console setup

1. Go to [search.google.com/search-console](https://search.google.com/search-console)
   and add the property `heymeowcat.is-a.dev` (Domain type, DNS TXT).
2. Copy the verification token and set it in the build environment:

   ```bash
   # .env (local) — or as a repository secret in CI
   PUBLIC_GOOGLE_SITE_VERIFICATION=your_token_here
   ```

   `src/layouts/Layout.astro` emits it as a `google-site-verification` meta tag
   automatically. No code change is needed.
3. Under **Sitemaps**, submit:
   `https://heymeowcat.is-a.dev/wifiheatmap-site/sitemap.xml`
4. Under **URL Inspection**, request indexing for `/` and each feature page.
5. Under **Page Experience**, monitor the Core Web Vitals report.

> The `is-a.dev` subdomain cannot be verified with a file-based method or with
> an HTML tag pointing at a different host — use the DNS TXT record, or move to
> a custom domain (recommended for a commercial product) and switch to
> file-based verification.

## HTTPS & security headers

| Host | How HTTPS is enforced |
| --- | --- |
| GitHub Pages | **Settings → Pages → Enforce HTTPS** (this is the only step required) |
| Netlify / Cloudflare Pages | `public/_redirects` (http → https 301) + `public/_headers` |
| Apache / Netlify classic | `public/.htaccess` (301 + `mod_headers` + `mod_deflate` + caching) |

`public/_headers` also sets `Strict-Transport-Security`, `X-Content-Type-Options`,
`X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` and long-lived
immutable caching for fingerprinted assets.

## Deployment

The GitHub Actions workflow in `.github/workflows/` builds and publishes to
GitHub Pages. It:

1. installs dependencies with `npm ci`,
2. regenerates the image assets (`npm run assets`),
3. builds with `astro build --site --base` so the base path always matches the
   deployment,
4. runs `npm run seo:audit` against the built output and **fails the deploy** if
   the SEO checks regress,
5. uploads `dist/` as the Pages artifact.
